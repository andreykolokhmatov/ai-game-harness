# AI Game Development Harness

Локальный source-available Harness (продавать Harness нельзя, игры с ним делать и продавать можно; см. docs/ARCHITECTURE.md, раздел 8.1): короткая идея игры → цепочка AI-агентов (через Claude Code как внешний процесс) → готовый к публикации Godot-проект. Специализация: Godot → Web; Yandex Games после MVP (сначала цепочка должна делать хорошие игры). Архитектура модульная.

Исходное ТЗ: docs/original_brief.md. Актуальный план: docs/PLAN_v2.md (при расхождении приоритет у PLAN_v2).

## Принципы
- Harness это оркестратор. Код игры пишет Claude Code, Python управляет состоянием, ролями, бюджетами, чекпоинтами.
- Истину о качестве игры определяют инструменты (Godot, тесты, Playwright), LLM лишь интерпретирует результаты.
- Кто сделал работу, тот её не принимает. Evaluator независим и ничего не исправляет.
- Любой цикл ограничен: итерации, время, бюджет, circuit breaker.
- Состояние это append-only журнал событий; состояние Harness хранится вне Git-репозитория игры.
- Требования Yandex Games только из официальной документации, у каждого есть источник. Ничего не выдумывать.
- Model ID только в config/models.yaml, никаких хардкод-путей, секретов и привязки к конкретной ОС. Использовать pathlib.
- Целевая платформа запуска: Linux. Код должен работать и на ноутбуке разработчика (Windows); платформенно-зависимые места (Xvfb, завершение процессов) прятать за тонкими функциями.
- ClaudeCodeRunner это интерфейс с заменяемыми адаптерами.
- Caveman и прочие skills необязательны.

## Правила работы
- Пока docs/ARCHITECTURE.md не одобрен пользователем, реализацию не писать.
- Работать итеративно: сделать → запустить → проверить → закоммитить. Не создавать десятки файлов без проверки.
- Не спрашивать о мелочах, если решение очевидно; важные trade-offs объяснять.
- Не копировать чужие проекты, использовать их как reference.
